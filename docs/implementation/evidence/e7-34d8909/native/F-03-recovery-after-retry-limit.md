# F-03 — High: a failed third attempt cannot be abandoned through the controller

The negative E7 fixture used the immutable `34d89095ba75d6ae2707c3ed331ab4bda56573b6` export and three real Luna/high task attempts. Each attempt changed only `release.py`, reported its runnable acceptance failure honestly, and failed the controller's fixed-suite verification. The third attempt still accepts `1.2.003` (AC-002); its bound native child is terminal `completed`. These failures were deliberately injected to test the controller, not an assessment of model quality.

At the configured limit of three attempts, `retry` returned `retry_limit`. A fourth `prepare` returned `task_already_active`; no fourth child was launched. `review(pass)` returned `verification_required`, `close` returned `review_required`, `phase-ready` returned `phase_not_idle`, and `complete` returned `technical_complete=false`. Authorized `abandon` returned `active_task_requires_reconciliation` with `task_status=verification_failed`.

The documented recovery route was also exercised. `interrupt` and `resume` succeeded, and `resume` attested the exact bound Luna/high session as terminal. Because a result had already been recorded, `resume` did not move the task to `reconciliation_required`; `reconcile(disposition=retry)` returned `reconciliation_not_required`. A subsequent authorized `abandon` again returned `active_task_requires_reconciliation`. The controller therefore offers no supported transition in this state to retire the active task while preserving the retry limit and recorded failure.

Impact: the negative disposable repository retains its active cross-worktree ownership lease, preventing a new run in that repository. Its code, receipts, event history, three-attempt budget, and failed verification remain intact. This is a recovery/control defect in the evaluated candidate; no controller source, state file, lease, or event was edited to bypass it. The positive fresh and legacy runs closed independently and released their leases.
