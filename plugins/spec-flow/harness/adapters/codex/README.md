# Native Codex adapter

The controller is local Python for contracts, approvals, events, packets, verification, and state transitions. It does not enumerate or invoke Codex agent tools. The orchestrator uses native tools exposed by its host to spawn, wait for, interrupt, and inspect agents. At run start it checks that those capabilities and host session logs are available and that execution is in an isolated linked Git worktree; if any requirement is missing, orchestration blocks with a clear reason. No external model API or silent model fallback is part of this adapter.

## Host handoff

1. Establish an orchestrator matching the selected model/effort (the run snapshot when resuming). If the calling session differs, spawn a child with that exact profile as the actual run owner. Use its host session ID as controller owner.
2. Start an authorized run and prepare one task. Read its immutable packet by path and hash. Build a bounded child prompt from selected task/steps, relevant acceptance criteria and decision excerpts, allowed paths, expected checks, and source digests. Preserve the full packet locally as the audit source.
3. Spawn one child with the pinned implementer model/effort with `fork_turns: "none"`. Record the native response's agent ID. Resolve the child's host session ID and bind it to the prepared attempt. Do not send a second implementation attempt while this agent is active.
4. Wait for completion or inspect a stalled agent. Record the actual result and diff, then ask the controller to verify the real worktree. The orchestrator checks each task and requests changes only with a failure hypothesis.
5. At phase end, spawn a distinct child with the pinned reviewer model/effort with isolated history. Send a bounded review packet covering the stable phase diff, approved requirements, and controller evidence. Attest its session and record its verdict. Close only when verification and review remain current.
6. On interruption, inspect native agent status and file changes before `resume` and `reconcile`. If the original child is still active, wait or interrupt deliberately; do not replay work because its final message is missing.

For an interrupted owner that cannot continue, `takeover` requires the old owner session and any bound implementer session to have terminal host lifecycle records. Supply the previous owner ID, a newly attested owner ID, and a concrete reconciliation note. The controller records that inspection and retains the existing authorization and phase list. Active or unreadable owner/child records make takeover fail closed.

## Host attestation

For this host, the adapter resolves a rollout file under `$CODEX_HOME/sessions/` (or `~/.codex/sessions/`) whose filename ends in the requested session ID. It checks `session_meta.payload.id`, `session_meta.payload.source.subagent.thread_spawn.parent_thread_id` and `agent_path`, and every task-bearing `turn_context`. Each context must match `payload.model` and `payload.collaboration_mode.settings.reasoning_effort` for its role. Missing, malformed, contradictory, unreadable, or unrecognized records fail closed. Each role uses its exact model/effort frozen in the run, with distinct owner/reviewer session IDs; [profile configuration](../../contracts/profiles.md) defines defaults and legacy compatibility. A result field stating a model name cannot establish this.

Before `start`, call `capabilities` with an `inventory_reference`, `operations` booleans, and nonempty `probe_evidence` references for `spawn_agent`, `wait_agent`, `interrupt_agent`, and `list_agents`. Python cannot enumerate those native tools or verify external references; it validates that the host supplied them and attests the configured owner from the local session log. The host orchestrator performs the probes and agent operations. Host attestations save hashes of the exact metadata, turn-context, lifecycle, and delegation records used, without copying conversation content. After `prepare`, include `SPEC_FLOW_PACKET_SHA256=<packet_sha256>` in the implementer prompt and use the returned `native_task_name` in `spawn_agent`'s `task_name`. It is `luna_` plus the lowercase SHA-256 of that full marker. This also works when the host encrypts the delegated message in its logs: the adapter verifies the hash-bearing native spawn call, its call-ID-linked output path, and the child session's parent/path lineage. It does not claim to inspect encrypted prompt text. If the message is visible, the exact marker in the child user prompt is also accepted. Assistant prose/output never attests delegation. Bind the canonical native agent path/ID returned by spawn, child session ID, and `agent_path` with `bind-agent`; the path/ID must equal `session_meta`'s host-recorded agent path. Results are accepted only after the bound child log shows terminal `task_complete`, packet-specific delegation evidence, correct parent/path, and the right profile. Report `files_modified`, `checks`, `evidence`, `blockers`, and `summary`; the controller compares changed paths with the actual baseline diff.

For `phase-ready`, use its returned `native_task_name` in the independent reviewer with its pinned profile `spawn_agent` call. It is `review_` plus the lowercase SHA-256 of the full `phase_marker` (`SPEC_FLOW_PHASE_REVIEW=<run>/<phase>/<tree>`), binding the reviewer invocation to this exact run, phase, and reviewed tree. A no-spawn reconciliation fails closed if it finds any child created during the attempt whose task association cannot be established.

Session logs provide local operational attestation, not cryptographic identity or a security boundary against someone who can rewrite those logs. The controller still validates approved digests, actual file scope, verification output, and code fingerprint. A task packet's allowed-path list is guidance plus later detection, not an OS permission boundary. Native host permissions and worktree isolation remain the preventive controls.

## Cross-worktree ownership

Resolve the repository's Git common directory and keep a persistent controller registration there, protected by a short-held filesystem lock. Record run ID, release, canonical worktree path, and attested owner session. The registration remains active after the lock is released between calls. Every mutating operation confirms ownership; a second worktree cannot start an overlapping run. Remove it only after completed closure or an explicit reconciled abandonment, never because its timestamp is old. An explicitly authorized `abandon` also handles an exhausted `verification_failed` task: the controller reattests the owner/lease and exact bound child as terminal, records the unresolved task/attempt and attestation, then releases ownership. It preserves failures and the cross-run retry budget; a live or unattestable child blocks release. Production implementation runs require the controller root to be the root of an isolated linked Git worktree. A non-Git or primary checkout may initialize the harness, draft strategy documents, and preview migration, but cannot start native implementation. If the common directory cannot be resolved or safely written, fail closed rather than relying on separate worktree-local locks.

## Audit retention across phase commits

Keep compact approval and execution events and durable evidence references in tracked project records. Generated state, immutable context packets, and bulky command logs may be ignored because they can be reconstructed or retained separately. The code-phase commit matches the independently reviewed staged tree. A phase-commit receipt written afterward is allowed as a pending audit-only change and is included in the next reviewed phase commit. After the last code phase, one audit-housekeeping commit captures its receipt and compact evidence; do not create a receipt for that housekeeping commit. This bounded checkpoint prevents a commit-record loop while preserving audit history when the worktree is archived.


If a process stops after `prepare` and before `bind-agent`, resume and inspect the native `list_agents` inventory for that owner. `reconcile` with `disposition: "no_spawn"` requires `native_inspection` with `owner_session`, a nonempty `inventory_reference`, a UTC `checked_at` newer than preparation, and `agents` entries containing `agent_path` and terminal `status`. The adapter attests the configured owner, scans only local session metadata for that parent's children, checks delegated user prompts for the exact packet marker, and records hashes of the inventory and matching local host records. A packet-marked child blocks no-spawn and must be bound; any active native agent or task-file change blocks it. This inventory reference is host supplied and not cryptographically verified by Python.

New-run capability reports also require `model_catalog_reference` and a host `model_catalog` of IDs and `reasoning_efforts`; preserve the snapshot/reference without claiming Python independently enumerates host models. For existing-run preflight pass `run_id` to capabilities so current config edits do not change its attested profile. See [profiles](../../contracts/profiles.md).
