# Native Codex adapter

The controller is local Python for contracts, approvals, events, packets, verification, and state transitions. It does not enumerate or invoke Codex agent tools. The Sol orchestrator uses native tools exposed by its host to spawn, wait for, interrupt, and inspect agents. At run start it checks that those capabilities and host session logs are available and that execution is in an isolated linked Git worktree; if any requirement is missing, orchestration blocks with a clear reason. No external model API or silent model fallback is part of this adapter.

## Host handoff

1. Establish an attested Sol high orchestrator. If the calling session uses Astra or another model, spawn a Sol high child as the actual run owner. Use its host session ID as controller owner.
2. Start an authorized run and prepare one task. Read its immutable packet by path and hash. Build a bounded child prompt from selected task/steps, relevant acceptance criteria and decision excerpts, allowed paths, expected checks, and source digests. Preserve the full packet locally as the audit source.
3. Spawn one Luna high child with `fork_turns: "none"`. Record the native response's agent ID. Resolve the child's host session ID and bind it to the prepared attempt. Do not send a second implementation attempt while this agent is active.
4. Wait for completion or inspect a stalled agent. Record the actual result and diff, then ask the controller to verify the real worktree. Sol checks each task and requests changes only with a failure hypothesis.
5. At phase end, spawn a distinct Sol high reviewer with isolated history. Send a bounded review packet covering the stable phase diff, approved requirements, and controller evidence. Attest its session and record its verdict. Close only when verification and review remain current.
6. On interruption, inspect native agent status and file changes before `resume` and `reconcile`. If the original child is still active, wait or interrupt deliberately; do not replay work because its final message is missing.

For an interrupted owner that cannot continue, `takeover` requires the old Sol session and any bound Luna session to have terminal host lifecycle records. Supply the previous owner ID, a newly attested Sol owner ID, and a concrete reconciliation note. The controller records that inspection and retains the existing authorization and phase list. Active or unreadable owner/child records make takeover fail closed.

## Host attestation

For this host, the adapter resolves a rollout file under `$CODEX_HOME/sessions/` (or `~/.codex/sessions/`) whose filename ends in the requested session ID. It checks `session_meta.payload.id`, `session_meta.payload.source.subagent.thread_spawn.parent_thread_id` and `agent_path`, and every task-bearing `turn_context`. Each context must match `payload.model` and `payload.collaboration_mode.settings.reasoning_effort` for its role. Missing, malformed, contradictory, unreadable, or unrecognized records fail closed. The implementer is `gpt-6-luna`/high; orchestrator and reviewer are `gpt-6-sol`/high, with distinct session IDs. A result field stating a model name cannot establish this.

Before `start`, call `capabilities` with an `inventory_reference`, `operations` booleans, and nonempty `probe_evidence` references for `spawn_agent`, `wait_agent`, `interrupt_agent`, and `list_agents`. Python cannot enumerate those native tools or verify external references; it validates that the host supplied them and attests the Sol owner from the local session log. The host orchestrator performs the probes and agent operations. Host attestations save hashes of the exact metadata, turn-context, lifecycle, and packet-marker records used, without copying conversation content. After `prepare`, include `SPEC_FLOW_PACKET_SHA256=<packet_sha256>` verbatim in the Luna task prompt. Bind the canonical native agent path/ID returned by spawn, child session ID, and `agent_path` with `bind-agent`; the path/ID must equal `session_meta`'s host-recorded agent path. Results are accepted only after the bound child log shows terminal `task_complete`, the exact packet marker, correct parent/path, and the right profile. Report `files_modified`, `checks`, `evidence`, `blockers`, and `summary`; the controller compares changed paths with the actual baseline diff.

Session logs provide local operational attestation, not cryptographic identity or a security boundary against someone who can rewrite those logs. The controller still validates approved digests, actual file scope, verification output, and code fingerprint. A task packet's allowed-path list is guidance plus later detection, not an OS permission boundary. Native host permissions and worktree isolation remain the preventive controls.

## Cross-worktree ownership

Resolve the repository's Git common directory and keep a persistent controller registration there, protected by a short-held filesystem lock. Record run ID, release, canonical worktree path, and attested owner session. The registration remains active after the lock is released between calls. Every mutating operation confirms ownership; a second worktree cannot start an overlapping run. Remove it only after completed closure or an explicit reconciled abandonment, never because its timestamp is old. Production implementation runs require the controller root to be the root of an isolated linked Git worktree. A non-Git or primary checkout may initialize the harness, draft strategy documents, and preview migration, but cannot start native implementation. If the common directory cannot be resolved or safely written, fail closed rather than relying on separate worktree-local locks.

## Audit retention across phase commits

Keep compact approval and execution events and durable evidence references in tracked project records. Generated state, immutable context packets, and bulky command logs may be ignored because they can be reconstructed or retained separately. The code-phase commit matches the independently reviewed staged tree. A phase-commit receipt written afterward is allowed as a pending audit-only change and is included in the next reviewed phase commit. After the last code phase, one audit-housekeeping commit captures its receipt and compact evidence; do not create a receipt for that housekeeping commit. This bounded checkpoint prevents a commit-record loop while preserving audit history when the worktree is archived.


If a process stops after `prepare` and before `bind-agent`, resume and inspect the native `list_agents` inventory for that owner. `reconcile` with `disposition: "no_spawn"` requires `native_inspection` with `owner_session`, a nonempty `inventory_reference`, a UTC `checked_at` newer than preparation, and `agents` entries containing `agent_path` and terminal `status`. The adapter attests the Sol owner, scans only local session metadata for that parent's children, checks delegated user prompts for the exact packet marker, and records hashes of the inventory and matching local host records. A packet-marked child blocks no-spawn and must be bound; any active native agent or task-file change blocks it. This inventory reference is host supplied and not cryptographically verified by Python.
